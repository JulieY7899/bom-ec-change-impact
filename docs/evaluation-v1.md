## 测试覆盖了哪些决策风险

| 风险 | 本轮验证 |
| --- | --- |
| 多层追溯遗漏或错误关联 | 已知 BOM 路径、成品和订单的合成预期；同一销售订单头下无关生产订单不纳入 |
| 历史结果混入当前核查 | 同 BOM 标签、不同核查批次的结果隔离 |
| 用量证据不足却输出完整总量 | 替代组、缺失路径、旧用量不一致、多个来源、溢出等情况保留复核 |
| 把日期筛选当版本迁移 | 验证同一快照在两个日期下的路径差异，并保留适用边界 |
| 缺失订单量被当成零 | 派生量缺项、部分合计、单项与批次 HTTP 报告、真实零、无关联订单分别验证 |
| 已完成但交付未知却被当成可继续使用 | 保留核查对象，给出保守候选处置，不推断“均未开工” |
| 数据被可选模型功能外发 | 即使提供合成 API Key，也不调用外部请求；HTTP 模型接口禁用 |
| 跨站调用本地服务 | 拒绝外部 Host、外部 Origin 和不匹配的来源端口 |
| 生成报告与保存结果不一致 | 实际本机 HTTP 测试覆盖分析、批次汇总和报告导出 |

这些测试使用内置虚构数据、合成输入和临时数据库。它们验证声明的具体行为，不构成生产系统可用性、业务收益或安全认证。

## 复现方式

从项目根目录运行：

```bash
python3 scripts/verify.py
python3 scripts/run_example.py --check
```

需要更新本机验证记录时：

```bash
python3 scripts/verify.py --report examples/verification.json
```

需要重生成示例报告与结果图时：

```bash
python3 scripts/run_example.py
python3 scripts/render_example.py
```

结果图使用真实运行结果的计数与路径生成 SVG；它是解释结果的示意图，不是页面截图。PNG 是同一 SVG 的静态导出。

## 已知业务口径

订单数量未知时返回空值并显示“待补数据”；空的候选订单集合允许显示为零。成品数量仅用于候选对象核查，不等于组件净需求。

当前内部单项结果以确认产量推导未完工量，页面/API 分组报告以交付量推导待交付量；界面统一称“待交付/未完工成品”。后续需要将两项指标明确分开。这个版本没有将它们用于采购下达或真实供需平衡。
