# 业务核查工作流

打开首页进入「业务核查工作流」。可以先用对话整理核查参数，再按预检列出的需要准备 Excel 导出。普通模式接受展开 BOM，按工程版本核查需要明确定义的 EBOM、BOM 行和订单引用。可选采购及到货资料沿用已有模板。

## 从问题到结果

| 步骤 | 输入 | 可检查的输出 |
| --- | --- | --- |
| 参数确认 | 业务问题、角色、核查模式、变更类型、物料或 BOM 行、拟生效日 | 可编辑参数。识别不到的范围由业务人员填写 |
| 数据预检 | 已确认参数和当前导入快照 | 来源和行数、缺字段、版本引用或行适用性待核。必填项不足时无法运行 |
| 01 数据准备 | 在预检结果中点「带入 01 数据准备」 | 沿用已填参数，列出要核对的资料和当前快照覆盖情况。可返回核查表继续操作 |
| 规则核查 | 预检后的结构化参数 | BOM 路径、销售行、生产工单、采购承诺或版本引用，以及原始来源 |
| 角色核查与报告 | 规则结果 | 角色相关事实及待复核事项。网页和下载使用同一份运行记录 |

预检绑定当前导入快照。成功导入后，页面用同一组参数自动重新预检。核查参数用于筛选和核对导出范围，Excel 由使用者选择导入。原始业务问句用于参数识别，运行记录保存确认后的字段、业务关注项和证据。

重新打开页面可查看当前快照中最近一次工作流结果。替换导入快照后，旧快照结果随本机快照备份保留。

可用虚拟演示快照试试「我是采购，COMP-001 无法及时采购，替代采购件为 COMP-998，有什么影响？」。助手识别采购角色、替换类型、原组件和新组件，只追问拟生效日期。补充「2026/12/1」后可以一键填入核查表。已有值的改动会在填入前显示。切换成品、工厂或版本后，需要重新确认目标 BOM 行。

也可以打开核查表直接编辑。对话消息保留在当前页面，运行记录使用已填入的结构化参数和识别出的业务关注项。选择研发查看结构，选择销售查看订单行和需求日，选择制造查看工单，选择工程查看工程路径与版本引用。

工程模式示例可导入「工程版本与订单引用示例」，再输入「从销售角度，成品 FG-T1，工厂 PLANT-T，工程版本 ENG-V2，BOM 行 V2-L2，2026-12-01 把 PART-OLD 换成 PART-NEW，哪些订单行要复核？」。采购工厂和采购库位用作采购核查范围，工程版本工厂用作版本定位范围。

## 03 影响核查中的工程辅助分析

1. 选择工程角色，确认并运行核查，然后点「查看 03 影响核查」。
2. 展开「工程辅助分析 · PPT 知识库」，选择已脱敏的 `.pptx` 并提取逐页文本。审核、编辑并勾选可供工程参考的摘录，再点「加入知识库」。重新索引同一份文稿会更新其摘录。
3. 点「检索工程知识」。最多显示三条相关摘录、文稿编号与原页码。工程辅助材料仅在此处查看。标准网页结果和下载报告使用规则证据。

标准 PPTX 限 12 MB、最多 80 页。图片、备注和 `.ppt` 需要先整理成可提取的 PPTX 页面文本。原始 PPT 文件不保存，审核后的文本和索引保留在本机数据库及快照备份中。工程入口根据已完成的核查角色显示，当前工具以本机单人使用为前提。

`PYTHONPATH=src python3 -m unittest tests.test_workflow -v` 覆盖缺字段、快照变更、对话字段提取、预检数据交接、确切版本命中与排除、工程知识访问范围和报告一致性。完整回归以 README 的验证命令为准。
